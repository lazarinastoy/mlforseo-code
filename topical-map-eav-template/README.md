# Topical map template + generator (EAV-based)

A free Google Sheets template by **Lazarina Stoy, MLforSEO**. You describe one central entity, the attributes people use to describe or filter it, and the values each attribute takes. The sheet generates a topical map from that: a pillar page, one cluster (hub) page per attribute and one supporting page per value, each with a suggested title, slug, intent, format, internal links, coverage against your existing URLs and a priority score.

**Get the Google Sheet:** [Make a copy](https://docs.google.com/spreadsheets/d/13UYd3SMuj9bc9b9OtdoNW0BLtEFE_hvjhnS8TDo71HA/copy) (opens a copy in your own Google Drive). Prefer Excel? Download [`topical-map-eav-template.xlsx`](topical-map-eav-template.xlsx); see [SETUP.md](SETUP.md).

## Why EAV

EAV (entity, attribute, variable or value) is a data-modelling pattern borrowed from database design. The MLforSEO post [What is the EAV model in SEO?](https://www.mlforseo.com/ml-fundamentals/what-is-the-eav-model-in-seo-a-practical-framework-for-semantic-keyword-research/) explains it in full. This template uses it as a planning lens: a structured way to list what your audience wants to know about an entity, decide which combinations deserve a page, and find gaps. It doesn't claim that any search engine ranks pages this way. The MLforSEO posts call the third part the *variable*; here it is the *value* column, the specific value an attribute takes.

## What's inside

| Tab | What it does |
|---|---|
| Start here | Purpose, steps, how the map is built, legend, credits |
| Entity | The central entity, entity type, pillar URL and three title patterns (`{entity}`, `{attribute}`, `{value}`) |
| Attributes | One row per attribute: type (Finite / Finite with a cutoff / Infinite), cutoff rule, typical intent, business relevance 1-3, include?, optional cluster title and title pattern, hub URL. Calculated: values listed and kept, coverage, and a check column |
| Values | One row per value: is it an entity itself, real user benefit (Yes / Unsure / No), optional volume, existing URL. Calculated: keep?, position, sibling |
| Topical Map | Generated: level (Pillar / Cluster / Supporting), attribute, value, title, slug, links up, across and down, intent, format, existing URL, Covered or Gap, search volume, priority |
| Combinations | Crosses two attributes into a grid of long-tail ideas, with a warning if either is infinite |
| Dashboard | Attributes and values kept, covered vs gaps, coverage per attribute, open checks |
| Lists | Intent → suggested format mapping |

## How the map is built

* **Pillar**: the central entity. **Clusters**: included attributes, in the order you list them. **Supporting**: kept values (attribute included and real user benefit isn't `No`).
* **Infinite attributes** (names, URLs, slogans) are flagged if you include them, following the finite / infinite distinction in the EAV post. A practically-infinite attribute needs a cutoff rule ("brands we stock", "cities over 100,000 people").
* **Links up to**: supporting pages link to their cluster page, cluster pages to the pillar. **Links across to**: the next value in the same attribute, looping back to the first, so siblings link to each other. **Links down to**: how many child pages each hub has.
* **Format**: sub-entities get an entity page; other values get a format from their attribute's intent (guide, comparison, category listing, landing page).
* **Priority**: pillar 100; cluster = relevance × 25 (+10 if it's a gap); supporting = relevance × 20 + volume points (max 20, log scale) + 10 if it's a gap + 5 if real user benefit is `Yes`.

The map is generated by formulas, so copy it and **paste as values** into a new tab once you're happy, then edit titles and add notes there.

## Formulas

Plain `INDEX`/`MATCH`, `COUNTIF(S)`, `SUMIFS`, `SUMPRODUCT`, `SUBSTITUTE`, `IF` and `IFERROR`, so it works the same in Google Sheets and Excel (no `FILTER`, `UNIQUE`, `XLOOKUP`, `LET` or `LAMBDA`). Helper columns give each kept value a running number; the map reads those numbers back with `INDEX`/`MATCH`. Capacity: 50 attributes, 500 values.

## Sample data

A fictional running shoe shop: entity "Running shoes", 8 attributes (terrain, distance, foot type, cushioning, brand, runner level, price, runner name) and 28 values, including an excluded infinite attribute and a value marked "no real user benefit". The sample builds a 34-row map with 9 pages covered and 25 gaps.

## Filling the Values tab faster

The Values tab is where most of the work is. Two free MLforSEO notebooks help: the [Knowledge Graph API extraction notebook](https://www.mlforseo.com/resource/knowledge-graph-api-extraction-and-entity-relationship-analysis-for-semantic-keyword-research-notebook/) (related entities and types) and the [multi-platform autocomplete notebook](https://www.mlforseo.com/resource/multi-platform-autocomplete-keyword-research-with-google-search-youtube-and-places-apis-notebook/) (the attributes and values people actually type). A dedicated generator notebook that drafts the map from a seed entity isn't part of this folder yet.
